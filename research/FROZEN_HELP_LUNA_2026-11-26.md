# Frozen Luna HELP: optional native objects, independent proof completion

## Registered before model sampling

Question: can independently generated native checked objects open mathematical
paths for a weaker reasoning-effort setting that direct proof attempts do not?
The decisive diagnostic is a Low continuation that closes with multiple
Medium-generated objects jointly but no isolated object/ordinary Low
continuation closes, and exact single-object deletion replays establish
local dependence on at least two independently generated facts.
A general aid or direct solve (including the whole goal as object) is legal
but does not establish composition. If all roots are already easy, no
composition can be assessed at that boundary; do not increase samples for
publication polish. This is a bounded frozen discovery experiment, not RL
training or evidence of autonomous parameter learning.

User explicitly selected gpt-6-luna/low and gpt-6-luna/medium via Codex CLI.
Use Low actor, Medium partner; "Low/Medium" are reasoning-effort settings,
not verified parameter sizes. No model tools, external resources, shell,
web, file lookups or subagents in rollout sessions; isolate using the
previous CLI runner's ephemeral read-only pattern, audit every event.

Local preflight fails cluster CUDA/Ray/pinned Mathlib dependencies; an exact
Lean v4.9.0-rc1 arm64 executable exists under artifacts/lean-cli-verifier.
Use independent native core Lean (import Lean), no Mathlib, for this new
small experiment, not a modification of the historic verifier/baseline.
Fixed four authored roots with checked fixture proofs (fixtures are private
to verifier, never supplied to model), two accumulator/list/tree tasks and
one linear recurrence plus alternating split/weave. Freeze manifest
and source before CLI calls. Each root context is just its original native
binders and target; HELP location held at root for this diagnostic, not
learned or handpicked intermediate assistance. This tests object content,
not when to request help.

Each root: K=3 independent Medium typed-object responses, K=3 direct Medium
proofs, K=3 bare Low proof proposals, K=3 Low continuations receiving each
single respective checked object (or empty if failed/declined), K=3 Low
continuations receiving all independently checked objects in fixed trial order.
This is 60 total CLI calls, fixed count, no replacements. The same actual
Medium bank is reused for isolated and bundle counterfactual diagnostics;
charge its full work to either arm, distinguish physical reuse. Each assisted
comparison has three Medium and three Low requests; direct portfolio control
is three direct Medium plus three bare Low. CLI does not expose a dependable
fixed generated-token ceiling or seed; log actual input/output/reasoning tokens,
wall times, exact commands and model IDs. Equal request counts and effort
are matched, **not exact token or hardware budgets**. Do not claim strict
matched-compute superiority.

Partner output is one arbitrary local binding have/let, type A:Sort u,
and proof/value of A, or decline. No human preference for theorem, lemma,
invariant, size, wording or relation to G; P=G is legal. Lean validates the
typed term under the unchanged original context (independent of siblings).
Only verified objects enter actor context. Have's proof is hidden from actor;
let's term is shown as needed for computation. No rationale/explanations.
Invalid outputs leave no fact but consume the trial. Root proof is assembled
with original header and validated objects, then checked in a fresh Lean
process with fixed original declaration and allowed axioms propext,
Classical.choice, Quot.sound. No sorry/admit, shell/metaprogramming or new
axioms; reject out-of-scope code, timeouts and unresolved separate. No
intermediate reward or selection by perceived usefulness. All valid typed
objects and all outcomes preserved. For every accepted bundle continuation
with >=2 checked objects, replay unchanged continuation after each single
omission; also bare replay, no new model sampling. Reconcile all physical
verification calls. Local reliance alone not necessity in all proofs;
identical hypothesis name IDs across replay conditions. Record direct-root
objects and simple direct use manually as diagnostic.

Outcome: report ordinary standalone Lean verification, assisted root
success, direct portfolio and exact-call accounting; root-level descriptives.
A null, ceiling or inability to generate checked objects is informative,
not a reason to change panel after observing. No SFT, no RL, no new GPU
allocation. User has instructed keep proposal and critique notes verbatim.

## Discovery stage (before assisted continuations)

All 36 discovery sessions completed. Low bare 0/12; Medium direct 1/12
(walk). Medium HELP returns 3/12 independently verified objects (walk,
reverse, tree), each exactly its original target; split has none. No root
has two verified objects, so this run cannot establish bundle composition
even in principle. Complete the already registered isolated/bundle
continuations without changing prompts, bank or sample count. Direct-root
delegation was explicitly legal and is the scientifically important
observed degeneration. All retained objects are terminal goals, not
independent intermediate discoveries.

## Post-hoc diagnostic registration (no new generations)

Completion returned walk 3/3 bundle and 1/3 isolated, reverse 3/3 bundle and
1/3 isolated; tree and split zero. Tree's checked object is the exact root,
yet all four Low continuations receiving it ignore it (one rfl and three
induction attempts). Hypothesis: an existing verified object may be usable
but not consumed by the downstream policy. Replay a deterministic `exact
helpN` for each checked whole-root object under the same native assembly and
verifier; this tests interface correctness, not model performance.

One Medium candidate on reverse is the only proposed non-root intermediate:
type string starts `h : ∀ ...` (a local binder name/delimiter incorrectly
included in the type field). Its original check rejects type syntax before
establishing the proof. Test removal of precisely the leading `h : `
characters with unchanged term, independently; this tests whether a schema
format issue concealed a genuinely valid intermediate object. Do not admit
it to the original experiment or modify mathematical content. If it is
invalid, stop this diagnostic. Record every added verifier call.

All three exact-use diagnostics verify, including tree. The format-only
reverse candidate also verifies. This concrete finding motivates one
additional three-draw Low arm, `format_only_low`, on reverse **only**,
using the verified general accumulator lemma alone, no whole-target fact.
Its proof term remains hidden. The question is whether exposure to actual
nonterminal, model-discovered knowledge (rather than a full solution)
enables Low to complete a previously failed root. This is a post-hoc
discriminating interface diagnostic, not part of the original 60-call
panel. Compare against already registered reverse bare/empty exposures,
not a generalization claim. Do not alter the primary bank, or repeat if
the diagnostic fails. For each accepted continuation, replay unchanged body
without the lemma; the extra verification measures local reliance only.

## Final results (all 63 sessions, no model updates)

| Root | Bare Low /3 | Direct Medium /3 | Medium valid objects /3 | Isolated Low /3 | Bundle Low /3 |
|---|---:|---:|---:|---:|---:|
| walk | 0 | 1 | 1 | 1 | 3 |
| reverse | 0 | 0 | 1 | 1 | 3 |
| tree | 0 | 0 | 1 | 0 | 0 |
| split | 0 | 0 | 0 | 0 | 0 |
| Total | 0/12 | 1/12 | 3/12 | 2/12 | 6/12 |

The matched request-count direct portfolio solves one of four roots, while
each assisted portfolio solves two. But the partner itself already solved
three roots by producing the exact target; all eight primary accepted
assisted completions are simply `exact help0` or `exact help2`.
No root has two verified primary objects. The bundle's apparent advantage
therefore reflects more Low continuations receiving the *same single*
successful root handoff, not composition. There is no evidence of better
mathematical teamwork than direct offloading; the hypothesis did not receive
support at this boundary. Do not claim a literal proof-composition gain.

11 of 12 partner responses proposed the original goal directly or its
universally quantified counterpart. The one nonterminal candidate was
originally rejected for including a binder name in the type field. All
three accepted HELP objects verified as exact target facts. Tree Low
received that exact fact in four continuations, but produced `rfl` once
and three attempts at induction instead of applying it; all four reject.
Independent deterministic `exact help0` verifies under the same assembly.
This exposes a real *consumption* bottleneck even when the knowledge is
already sufficient; do not conflate it with discovery failure.

### A genuine model-generated Eureka object (separate format-only diagnostic)

The raw reverse candidate from Medium trial 0 included the type string
`h : ∀ as bs : List Nat, revAcc as bs = as.reverse ++ bs`. Removing only
the accidental leading binder name and colon yields the general lemma:

```lean
∀ as bs : List Nat, revAcc as bs = as.reverse ++ bs
```

The untouched Medium proof checks independently. This lemma is more general
than the original double-reverse target and is not itself the root conclusion.
Luna Low receives only the checked type, not its proof or the whole-target
object. It closes 2/3 fresh continuations; the accepted bodies are:

```lean
simpa [help0]
```

and

```lean
rw [help0, help0]
simp
```

Both unchanged bodies reject on omission. The third attempted essentially
the latter tactic sequence with invalid indentation and rejected. The
original Low bare reverse bank is 0/3, and both isolated empty-help draws
also reject. The valid mathematical object was discovered by Medium, not
provided by the author; the author removed a schema-format prefix only.
This is a post-hoc diagnostic, not an admitted primary success, randomized
effect estimate, evidence of composition of multiple facts, or evidence of
parameter learning. It supplies a concrete existence example of a novel
reachable conditional proof path through a verified model-generated
intermediate. It also shows how an unnecessary structured-output requirement
can obscure useful mathematical work.

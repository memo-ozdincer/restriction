# Can repaired prerequisites unlock new complete proofs?

Desired result: a checked invariant obtained from an actual failed base proof by
the registered scope repair enables the unchanged base model to solve a nonzero
or witness consumer that bare sampling fails. The completed consumer and the
repaired prerequisite must compose into one closed Lean proof. This tests the
proposal's idea that making one weak method usable can unlock another method.

The previous scope-only intervention succeeded only on invariant roots and did
not pass its two-schema training gate. Do not start that planned training study.
This is a different intervention: connect its verified outputs to consumers,
using a typed library interface. No weight update is included or implied.

Freeze the first accepted repaired base proof, by saved sample ordinal, for each
of the four invariant variants. Associate it with its existing nonzero and
Bezout consumers (eight tasks total). Require recursive function definitions to
match byte-for-byte after one identifier rename. Transfer the proof by that same
rename and recheck its closed theorem; do not author an invariant witness.

For each consumer, compare three conditions:

- **Bare:** the exact original task, no additional fact.
- **Linked:** instantiate the repaired invariant as a named local equality.
- **Irrelevant:** instantiate a checked reflexive equality between the output
  determinant and itself. It is valid but does not connect the output to the
  initial-state premise. The interface and local-fact name are the same.

The model sees the external theorem's type and the typed local instantiation,
but never the prerequisite proof body. The verifier includes that full body and
audits the transitive axioms of the final consumer theorem. Model-visible context
and verifier prelude are distinct, explicitly archived objects. Prefix-only
consumer checks must all reject: the library must not have already solved the
task. The irrelevant equality is longer than the informative one; exact prompt
token counts are reported. This is matched proposal/output capacity, not a claim
of identical input tokens or mathematical information across conditions.

Use pristine DeepSeek-Prover-V1.5-SFT 7B, the same pinned bytes as the completed
pilot, float32 Transformers SDPA, temperature/top-p 1, no top-k, 256 response
tokens, 32 proposals per task/condition (two batches of 16), fixed seed 20261122
plus task hash and batch offset. The same task/batch seed is used across the
three conditions. All 768 proposals count. No source, task, seed or prerequisite
is selected after consumer outcomes. All available proof routes count.

Use the unchanged parser, kernel and axiom audit, eight CPU verifier workers,
60 seconds per candidate, exact-complete-source caching only. Validate sixteen
linked/irrelevant library theorems, twenty-four unfinished consumer prefixes and
two invalid-proof controls before GPU allocation. A separate import warmup is
charged. Run in one at-most-one-hour H100 keeper allocation under def-zhijing,
with manual SSH launch and automatic release on completion or failure.

For every accepted linked sample, replay its exact continuation under both bare
and irrelevant prefixes, without generating more tokens. Cache identical full
sources, including primary checks already obtained. This adds at most 512 logical
ablation checks and determines whether the concrete program needs the supplied
fact or whether the prompt merely elicited a self-contained proof.

The registered exciting outcome requires at least one root in **each** consumer
schema with linked at least 8/32, bare at most 1/32 and irrelevant at most 1/32,
and at least one linked continuation on that root rejected under both ablations,
with every primary and ablation verdict resolved. Independently check exact artifact
provenance, definition renames, source reconstruction and counts. Preserve the
actual accepted consumer proofs and complete dependency chains.

These eight roots have been inspected and used in previous evaluations. This
is an inference-time composition test, not held-out generalization, evidence that
weights learned the procedure, or spontaneous discovery of the repair/library.
If successful, a learning experiment needs a fresh split and evaluation after
removing the entire library scaffold, with same-information replay controls.
Do not treat this result as retroactively passing the scope-only training gate.

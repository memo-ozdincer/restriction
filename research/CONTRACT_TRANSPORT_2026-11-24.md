# Compile a missing constructor from a verified hindsight contract

## Artifact sought

One unchanged model program, discovered under the wrong specification, becomes
a correct constructor for the original target through an automatically inferred
argument substitution. The compiler proves that substitution using only the
verified source contract. A separate transparent implementation check ensures
that the displayed executable function really satisfies the target as well.

The preceding learning comparison obtained verified hindsight data, but neither
replay nor context contrast constructed an original-sign solution. The next
mechanism supplies a constructive connection between contracts rather than
expecting likelihood suppression alone to discover it. This is a compiler stage
for generating verified training experience. No model improvement is claimed
unless a later learning experiment transfers without the compiler.

## Frozen source and target inputs

Use the first response selected by the completed hindsight mining rule:
`quadratic-composition/0`. Preserve its full proof under the inferred c=+1 law.
Extract its original function bytes without editing any operator or coefficient.
Do not select another source after outcomes. The signed quadratic contract family
and polynomial substitution language are supplied by the researcher.

Use the eight exact target statements from the completed hindsight evaluation:
both signs of the original, renamed, 2*d and d²+1 specifications. These are
inspected development targets; compiler success is not held-out model transfer.
No target implementation or reference proof is consumed by the transport solver.

Parse the target's signed norm coefficient and parameter name from its statement.
Solve coefficient equality for a substitution `p(d)=c0+c1*d+c2*d²`. The source
contract is universally quantified over its parameter, so instantiating it at
p(d) is legal when that signed coefficient matches the target. Require a unique
integer solution for all three coefficients. Synthesis consumes specifications,
not the body of the sampled program or any reference implementation.

## Checks and interpretation

For each target, generate four sources:

1. Logical transport: instantiate the verified existential source contract,
   construct the wrapper calling its abstract function at p(d), and derive the
   target with a fixed introduction/conversion/simplification/ring template.
   The proof does not unfold or inspect that function's implementation.
2. Executable transport: embed the exact extracted model lambda in a wrapper
   calling it at p(d), and check its whole target contract with the already
   fixed certificate generator. This authenticates the displayed executable
   witness separately from an opaque existential theorem.
3. Identity binding: use p(d)=d with the same logical template. Accept exactly
   the targets whose coefficient already matches the source contract; report
   these expected successes, rather than labeling every identity binding bad.
4. Wrong-sign binding: use -p(d) with the same logical template. All eight
   are expected to reject because the target coefficients are nonzero polynomials.

Also recheck the original source proof and a zero-function invalid source:
34 checks in all before deduplication. Every verdict must resolve. Require all
logical and executable transports to accept, and every control to match its
predicted outcome. Preserve sources, inferred coefficients, exact raw function
bytes and input hashes. Do not fix individual target certificates or expand the
substitution language after outcomes. Operational authoring failures, if any,
must be retained separately from mathematical outcomes.

An accepted transport is a new compiler-constructed program with a verified
origin, not an unchanged successful model response. The model's earlier pass
counts and failed gates stay unchanged. Substitution synthesis, theorem
instantiation and program reuse are existing techniques; this is not a novelty
claim or a revolutionary training result. Its useful outcome is an automatic
source of target-valid demonstrations derived from failed model attempts without
a target implementation supplied by a stronger model or a human.

Run this stage on CPU, commit its protocol and code before verification, and
publish all evidence. If the complete criterion passes, a subsequent learning
protocol must compare the resulting contract-closure data against hindsight
replay and evaluate with the compiler removed. No training is included here.
